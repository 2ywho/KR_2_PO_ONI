# Контрольная 2. Вариант 2. Task_3_Navigation

Запуск: Windows/NavigationLab.exe. Переносите папку Windows целиком.
Qt Creator: откройте Project/CMakeLists.txt или Project/Control_Work_02_Polymorphism.pro, выберите Desktop Qt 6, соберите и запустите цель NavigationLab.
Интерфейс написан на Qt Widgets и QPainter в main.cpp. Форма создаётся программно; отдельного .ui нет.

Все модели отделены в .h/.cpp. Абстрактные интерфейсы имеют virtual-деструкторы; реализации используют override. Поля закрыты. Вывод модели идёт через qDebug, интерфейс также показывает журнал.

## Проверка и защита
NavigationSystem задаёт get_position(), is_valid(), system_name(). GPS требует valid=true и минимум4 спутника. INS использует флаг готовности; Visual — отслеживание цели. NavigationManager хранит невладеющие указатели и каждый раз выбирает первый допустимый источник из списка GPS→INS→Visual. Поэтому после gps.set_valid(false) следующий запрос автоматически возвращает INS; при восстановлении GPS возвращается высший приоритет.
Общая функция отбора не знает конкретных классов, использует виртуальные методы, пропускает nullptr и проверяет координаты: конечные числа, широта−90…90, долгота−180…180, высота≥0. При отсутствии источников get_position() бросает исключение, а не возвращает выдуманную позицию.
Снимите готовность GPS, затем INS, затем Visual: статус покажет последовательное переключение и критический отказ. Восстановите GPS для возврата. Установите3 спутника или отрицательную высоту для ошибки GPS.
Поля координат Position открыты как в условии; состояние классов закрыто и изменяется методами. tests.cpp проверяет приоритет, восстановление, границу4спутника, nullptr, неправильные координаты и отсутствие источников.

Тесты: cmake --build build; ctest --test-dir build --output-on-failure. Qt6/bin и MinGW/bin должны быть в PATH. Данные являются учебными и не поступают с реальной аппаратуры.
