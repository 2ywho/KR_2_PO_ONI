# Пояснения для защиты

Sensor — абстрактный интерфейс: read(), is_ready(), name(), accuracy() объявлены чисто виртуальными. Виртуальный деструктор допускает безопасное удаление объекта через указатель на базовый класс.

NavigationSensor хранит закрытые поля ready_, count_, accuracy_. Публичные методы изменяют состояние; защищённый конструктор и count() доступны наследникам. GPS, GLONASS, VisualOdometry переопределяют read() и name(); готовность и точность наследуют от NavigationSensor. Переопределения обозначены override. Реализации методов модели вынесены в sensors.cpp.

choose_best_sensor получает const std::vector<Sensor*>&. Цикл работает с Sensor*, поэтому вызовы методов диспетчеризуются виртуально. Конкретные классы внутри алгоритма не проверяются. Пропускаются nullptr, неготовые источники, отрицательная погрешность, NaN и бесконечность. Строгое сравнение сохраняет первый источник при одинаковых значениях. Если кандидатов нет, возвращается nullptr и выводится qDebug-сообщение ERROR. Сложность O(n), дополнительная память O(1).

Указатели в векторе не владеют объектами. Объекты GPS, GLONASS и VisualOdometry живут в main до завершения цикла событий QApplication. Интерфейс при каждом изменении вызывает именно choose_best_sensor, затем виртуальный read() выбранного источника. Наличие и отсутствие указателя проверяется до обращения.

Демонстрация: исходно GPS 1,5 м; выключение GPS выбирает GLONASS 2,0 м; выключение всех выводит ошибку; сброс восстанавливает значения; изменение точности визуальной одометрии на 0,2 м делает её лучшей. В журнале отражаются действия. Количество признаков для VisualOdometry введено для явной семантики read(); метрическая точность — отдельная характеристика.

Проверки модели включают значения по умолчанию, показания, последовательное резервирование, все недоступны, nullptr, NaN, отрицательные значения, бесконечность, нулевую точность, равенство и пустой вектор. GUI-проверки нажимают реальные кнопки и меняют поля, сверяя выбранный объект и измерение.
