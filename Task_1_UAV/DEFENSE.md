# Объяснение для защиты

## Иерархия
UAV — абстрактный базовый класс: takeoff(), land(), type(), motor_count(), takeoff_type() и landing_type() являются чисто виртуальными. Создать UAV непосредственно невозможно. Quadcopter, Hexacopter и Octocopter переопределяют каждый метод с override и сообщают 4, 6 и 8 двигателей.

virtual ~UAV() = default обеспечивает корректное удаление производных объектов через указатель на базовый класс. std::unique_ptr<UAV> владеет каждым аппаратом, освобождение памяти автоматическое. Все поля закрыты. Вспомогательная changeFlightState() защищена: доступна наследникам, но не вызывающему коду.

## Динамический полиморфизм
print_vehicle_info(const UAV&) вызывает виртуальные методы объекта без if по типу и без приведений. Реализация выбирается во время выполнения по фактическому типу объекта. Функция принимает ссылку, поэтому null недопустим уже на уровне интерфейса. В вызывающем коде указатель дополнительно проверяется.

Ссылка const запрещает изменять аппарат при печати. Поэтому способы взлёта и посадки представлены отдельными const-методами, а команды takeoff()/land() изменяют состояние. Печать сведений сама по себе не запускает аппарат.

## Состояние и ошибки
Закрытый bool flying_ первоначально false. Взлёт меняет его на true, посадка на false. Повторный взлёт и посадка на земле выбрасывают std::logic_error. Сначала проверяется состояние, затем оно меняется: ошибочная команда не повреждает объект. GUI перехватывает исключения и пишет ошибку в журнал. Кнопки дополнительно предотвращают такие команды.

## Интерфейс
QPainter рисует число лучей и пропеллеров из motor_count(). QTimer обновляет угол вращения. Смена выбора не пересоздаёт аппарат, поэтому состояния независимы и сохраняются. qDebug используется в командах и print_vehicle_info; журнал удобен при запуске Windows-приложения без консоли.

## Что показать преподавателю
1. Открыть uav.h: абстрактный класс, virtual, override, закрытые поля.
2. Выбрать последовательно три аппарата: 4, 6, 8 пропеллеров.
3. Взлететь, проверить блокировку повторного взлёта, сменить аппарат и вернуться.
4. Посадить аппарат и вывести сведения.
5. Открыть print_vehicle_info: единый вызов через const UAV& без определения конкретного класса.
6. Запустить тесты: нормальный цикл и некорректные повторные команды проверены для всех классов.
